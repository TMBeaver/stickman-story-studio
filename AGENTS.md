# Production instructions

Read README.md, docs/WORKFLOW.md, docs/LONG_FORM.md and the selected style's reference before production. Use the accepted cafe example as the default visual benchmark when the user asks for Cozy Storytelling.

## User preferences

- Full-color 2D Cozy Storytelling, expressive minimalist white characters, purposeful animation and cinematic framing are accepted.
- Natural English storytelling narration is accepted. The old Microsoft David Desktop voice and crude procedural door animation are not the quality target.
- The current series is intended for TikTok: future shots must be composed natively in vertical 9:16. Deliver 1080x1920 edits, ten exact sixty-second parts, and portrait-safe captions. The first landscape film can be adapted with preserved wide scenes and background extension; do not describe that adaptation as native portrait generation.
- For uploads, name individual files Part 1 through Part 10 in story order. On screen show only the chapter title, without PART numbering or the overall series heading. Use larger, raised chapter titles and captions; the current upload edit uses 64px text, chapter title at y=300 and caption top at y=1190 on a 1080x1920 canvas.
- Longer films are composed from approved short clips. Preserve a coherent story, cast, important props, travel direction and narrator across cuts.
- Prefer to operate generation and assembly for the user when the required tools and authorization are available. Do not promise browser access before verifying it.

## Production discipline

1. Inspect existing manifests, outputs and approvals before starting. Do not regenerate accepted clips because a session restarted.
2. Resolve the story, duration, aspect ratio, style, language, voice and credit budget. Reuse supplied choices. Show a concrete script/shot plan for new stories and obtain required creative approval under the selected workflow.
3. Check actual Flow model, duration, resolution, output count and live credit quote. Generate one variant by default. Do not treat a paid plan or free allocation as unlimited generation.
4. Use the current host's browser tools and instructions. Never extract cookies, use private browser endpoints, bypass account checks or ask the user to paste credentials into chat. The user handles login and verification when required.
5. Preserve a canonical cast description in every clip prompt. Specify design, initial positions, timed object transfers and final state separately. Act through the entire body, expression and prop contact.
6. Prefer one fixed offscreen narrator. For longer films, a continuous external narration track can improve consistency when available and approved. Do not silently change provider or voice. Do not stretch speech to fill pictures.
7. Download original MP4s through supported controls. Probe and decode them; inspect chronological frames and actual playback. Report missing audio listening honestly. Do not claim screenshots prove natural voice or motion quality.
8. Record model, generation count, charged/quoted credits, assets, technical results, defects, trim points and user acceptance. Mark quoted estimates as estimates.
9. Fix only affected scenes and preserve originals. Never infer user approval from an encoding success.
10. Do not publish videos, buy credits, upgrade subscriptions or enable auto-reload without explicit authorization. Public repository updates requested by the user must exclude credentials, personal account data and private production URLs.
